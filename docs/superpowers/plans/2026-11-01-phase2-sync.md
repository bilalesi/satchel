# Phase 2 — Sync (GitHub first) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The vault directory is mirrored to a remote (GitHub private repo, or a local folder such as iCloud Drive) with compare-and-swap writes, per-item merge, conflict copies into history, rollback detection, and a "connect existing vault" flow for a second Mac.

**Architecture:** `RemoteStore` is a tiny async protocol (get / put-with-etag / list). `SyncEngine` runs the §7.3 algorithm against any `RemoteStore` using raw encrypted item bytes from `VaultStore`; it never needs plaintext except to merge two edits of the same item. The app wraps it in a `SyncCoordinator` that debounces, serialises runs and exposes status. Patterns: Strategy (backends), Facade (coordinator), optimistic concurrency (etag CAS), idempotent retry loop.

**Tech Stack:** URLSession, CryptoKit `Insecure.SHA1` (git blob ids), Security framework Keychain (token), XCTest with an in-memory remote and a `URLProtocol` stub.

**Spec:** `docs/INVESTIGATION.md` §5.3, §7.

## Global Constraints

- Remote layout identical to local: `vault.vhdr`, `manifest.vman`, `items/<uuid>.vitem`.
- Every remote write is conditional: `ifMatch: etag` to replace, `ifMatch: nil` to create-only. A conflict restarts the sync round; at most 3 rounds per run.
- Item write order on both sides: items first, manifest last.
- The Secure Enclave slot is **local-only** (`touchid.slot` next to the header) and never uploaded. `vault.vhdr` holds password slots only, plus `updatedAt`.
- Merge rule for the same item changed on both sides: newer `updatedAt` wins; the loser's secret fields go into the winner's `history` and the winner gets tag `conflict`. Nothing is dropped.
- Rollback rule: a remote manifest whose `generation` is lower than the last generation this device pushed or pulled is refused (`rollbackDetected`).
- Remote bytes are verified before use: header decodes, manifest MAC passes with local keys, item overview box opens with local keys and its header id/version match.
- GitHub: fine-grained PAT with `contents: read/write`, stored in the login Keychain under service `com.bilalesi.vault.github`; never in UserDefaults or logs. Writes serial (GitHub requirement).
- Network efficiency: one `list` call for `items/` per round; items whose remote etag equals the local git-blob sha are neither downloaded nor uploaded.
- Triggers: 2 s after a local change (debounced), on unlock, every 15 min while unlocked, on network regain. One run at a time; a request during a run sets a dirty flag and re-runs once.

## Review Focus

1. Remote returns a manifest that fails the MAC: nothing local changes, status shows the error. (Task 4 test.)
2. Two devices create the same new item id: impossible (UUIDs); two devices edit the same item: both values survive, newest on top. (Task 4 test.)
3. Network dies after items are uploaded but before the manifest: next run re-lists, sees matching blob shas, uploads only the manifest. (Task 4 test with a remote that fails on the Nth put.)
4. Second-device bootstrap with a wrong password: the downloaded directory is removed, nothing half-initialised remains. (Task 4 test.)
5. Token revoked: 401 surfaces as "Sign in to GitHub again", not as a corrupt vault. (Task 5 test.)

### Task 4: SyncEngine

**Files:** Create `Sources/VaultCore/Sync/SyncEngine.swift`, `Tests/VaultCoreTests/SyncEngineTests.swift`.

**Interfaces:**
- `public struct SyncReport: Sendable, Equatable { public var pulled: Int; public var pushed: Int; public var conflicts: Int; public var generation: UInt64 }`
- `public final class SyncEngine: Sendable { public init(store: VaultStore, remote: RemoteStore); public func sync() async throws -> SyncReport; public static func bootstrap(remote: RemoteStore, into url: URL, password: SecureBytes) async throws -> VaultStore }`
- Algorithm per round:
  1. `remoteManifest = get("manifest.vman")`. Absent → initial push (header create-only, all items create-only, manifest create-only) and return.
  2. Decode with local keys; `checkNotRolledBack(against: syncState.lastGeneration)`.
  3. Header: if remote `vault.vhdr` etag ≠ local blob sha → compare `updatedAt`; newer wins (`applyRemoteHeader` or mark header for upload).
  4. `remoteList = list("items/")`. For every id in local ∪ remote manifest: `lv`, `rv`, `base = syncState.synced[id] ?? 0`.
     - `rv > lv && lv == base` → pull (skip download if etag == local sha).
     - `lv > rv && rv == base` → push with `ifMatch: remoteList[path]` (nil if absent).
     - `rv > base && lv > base && rv != lv or bytes differ` → download, `mergeConflict`, write local, push merged with ifMatch.
     - equal → nothing.
  5. Merged manifest: versions = max per id, `generation = max(local, remote) + 1`, `headerHash` = local header. `put("manifest.vman", ifMatch: remoteEtag)`. `.conflict` → next round.
  6. `replaceManifest`, `saveSyncState(lastGeneration, synced = merged versions)`.
- `bootstrap`: download header, manifest, all items into `url` (temp dir then rename into place), `VaultStore.open` + `unlock(password:)`; on any failure remove the directory and rethrow.

- [ ] Tests with `InMemoryRemoteStore` and two `VaultStore`s in temp dirs (cheap KDF): `testInitialPushAndBootstrap`, `testEditPropagates`, `testDeletePropagates`, `testDisjointEditsBothKept`, `testSameItemConflictKeepsBoth`, `testRollbackRefused`, `testTamperedRemoteItemRejected`, `testManifestConflictRetries` (remote mutated between list and put), `testPartialUploadResumes` (put fails after 2 items; second run uploads the rest only), `testBootstrapWrongPasswordLeavesNothing`, `testUnchangedItemsAreNotTransferred` (counts of get/put on the fake).

### Task 5: GitHubStore + Keychain token

**Files:** Create `Sources/VaultCore/Sync/GitHubStore.swift`, `Sources/VaultCore/Sync/KeychainToken.swift`, `Tests/VaultCoreTests/GitHubStoreTests.swift`.

**Interfaces:**
- `public struct GitHubRepo: Codable, Equatable, Sendable { var owner: String; var name: String; var branch: String = "main"; var prefix: String = "" }`
- `public final class GitHubStore: RemoteStore { public init(repo: GitHubRepo, token: String, session: URLSession = .shared) }`
  - `get`: `GET /repos/{owner}/{name}/contents/{prefix}{path}?ref={branch}` with `Accept: application/vnd.github.raw+json`? No: use the JSON form to obtain `sha` and base64 `content` in one call (files < 1 MB; vault files are KBs). 404 → nil.
  - `put`: `PUT` same URL, body `{message, content(base64), branch, sha?}`; 200/201 → `content.sha`; 409 or 422 with "sha" in message → `.conflict`; 401/403 → `.unauthorized`.
  - `list`: `GET .../contents/{prefix}items?ref=` → `[{name, sha}]` → `["items/<name>": sha]`; 404 → `[:]`.
  - Headers: `Authorization: Bearer`, `X-GitHub-Api-Version: 2022-11-28`, `User-Agent: Vault`.
  - `public func verify() async throws -> String` — `GET /repos/{owner}/{name}` → `full_name`; used by "Test connection".
- `public enum KeychainToken { static func save(_ token: String, service: String) throws; static func load(service: String) -> String?; static func delete(service: String) }` using `SecItemAdd/Update/CopyMatching` generic password, `kSecAttrAccessibleWhenUnlockedThisDeviceOnly`.
